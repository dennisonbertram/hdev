# Notes on `hdev reap`

The `reap` command deletes Hetzner VMs that are no longer doing useful work and removes their entries from the jobs file so they stop appearing in `hdev ps`. It supports two filtering modes. `--max-age <duration>` deletes any tracked VM whose clock-age exceeds the given limit (regardless of its status), and also cleans up *untracked* VMs left behind by a crashed `submit`; a status of `waiting-on-limit` is exempted because the job is healthy but paused by a usage-quota reset. `--idle <duration>` is safer for jobs that are still young but may have stalled — it checks how long the agent has gone without writing a new file, and only deletes VMs in `running` or `starting` status whose idle time exceeds the threshold. Before deleting a VM, `reap` captures its token-usage row into the usage file so billing data is not lost. The `*` catch-all status handler deletes VMs that are in any unrecognised, terminal, or failed state (anything other than `running`, `starting`, `unreachable`, `gone`, or `waiting-on-limit`). After processing all tracked jobs, the surviving entries are written back to the jobs file, and any orphaned VMs found in Hetzner that are not in the jobs file are reported (or deleted if `--max-age` applies to them).
